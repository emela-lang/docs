関数と[データ型](/reference/data-types/#ジェネリックデータ型)に型パラメータを持たせるパラメトリック多相です。
型パラメータは **不透明** で、境界（トレイト制約）は [トレイト](/reference/traits/#境界bounds) が、
effect-row の多相は [エフェクト](/reference/effects/#effect-row-多相) が別に定めます。

## 型パラメータの宣言

名前付き関数は、関数名の直後の `<...>` に型パラメータを列挙します。

```emela
fn identity<T>(x: T) -> T uses {} { x }
fn map<T, U>(xs: Array<T>, f: (T) -> U uses {}) -> Array<U> uses {} { ... }
```

- 型パラメータは1つ以上をカンマ区切りで並べます。空リスト `<>` は書けません。慣習として大文字始まり。
- 宣言した型パラメータは、そのシグネチャ（引数型・戻り値型・`throws` 型）と本体の中で **型** として使えます。スコープはその関数定義に閉じます。

## 不透明性（parametricity）

型パラメータ `T` の値に対してできるのは次に限られます。

- `let` 束縛・引数として渡す・関数から返す
- `Array<T>` の要素にする / 取り出す、`Option<T>` などに入れる / 取り出す
- `T` が関数型のパラメータ（`f: (A) -> T`）なら適用する

具体型を要求する操作——算術・比較・[`match`](/reference/data-types/#match-式)・フィールドアクセス——は `T` に対してコンパイルエラーです。
これらが必要なら[境界（トレイト）](/reference/traits/#境界bounds)を付けます。この制約により、ジェネリック関数の観測可能な振る舞いは型引数によりません。

```emela
fn bad<T>(x: T) -> T uses {} { x + x }   -- error: `+` は具体的な数値型を要求する
```

## 推論

- 呼び出しでは型引数を **実引数の型から推論** します。明示的な型引数構文（`identity<Int>(x)`）は未導入です。
- 推論は、宣言上のパラメータ型（型変数を含む）と実引数の具体型を構造的に対応付けます。対応付けは `Array<D>` / `Option<D>` / `Name<D...>` / 関数型 `(D...) -> Dr` を再帰的に貫きます。
- すべての型パラメータが一意に定まらなければなりません。そのため各型パラメータは **少なくとも1つのパラメータ型の中に出現していなければなりません**。

```emela
fn first<T>(xs: Array<T>) -> Option<T> uses {} { array_get(xs, 0) }
first([1, 2, 3])       -- Array<T> ↔ Array<Int> → T = Int、結果は Option<Int>

fn pick<T>() -> T uses {}   -- error: `T` はどのパラメータ型にも現れない
```

## effect と throws

- ジェネリック関数も具体的な [`uses`](/reference/effects/) / [`throws`](/reference/errors/) を宣言できます。
- effect row を型変数で受ける多相は [effect-row 多相](/reference/effects/#effect-row-多相)（row 変数は sigil `'` 付きで `<...>` の外）。
- `throws E` の `E` に通常の型パラメータを用いること（単一の error 型を総称する）は有効です。複数 error 型の行多相は未導入です。

## 制限

- ジェネリックにできるのは **名前付き `fn` 定義** のみです。無名関数は型パラメータを宣言できません。
- 型パラメータに **境界は付きません**（完全に不透明）。境界は [トレイト](/reference/traits/#境界bounds) が与えます。
- ジェネリック関数は **直接呼び出し**（`name(args)`）でのみ使えます。第一級の値として束縛・受け渡しすること（`let f = identity`）は、型引数が決まらないため許可されません。

## 単相化と erasure

到達可能な `(関数, 具体型引数)` の組ごとに、型変数を具体型へ置換した単相版を生成します。
特殊化は推移的に展開されます。typed IR には型変数が一切現れず、backend は具体型だけを受け取ります
（[トレイトの erasure](/reference/traits/#解決の限界) と同じ不変条件）。ジェネリックデータ型のレイアウトも同様に単相化されます。
