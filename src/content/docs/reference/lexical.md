名前の種類は大文字と小文字で決まり、文の終わりは改行で決まります。どちらも字句解析の段階で確定し、名前解決の結果には左右されません。

このページは規範としての規則をまとめたものです。書き方の流れは [基本](/guide/basics/) を、EBNF は [文法](/reference/grammar/) を見てください。

## ソースファイル

- 拡張子は `.emel`、符号化は UTF-8 です。
- セミコロンは使いません。文は改行で終わります（例外は下の「行の継続規則」）。
- 空白はスペースとタブです。改行は `\n` か `\r\n` で、どちらも1つの改行として扱います。
- 単独の `\r` と、Unicode の空白（全角空白など）は認識できない文字になります（E1005）。

## コメント

```emela check
## 利用者を表す。
type User(
  ## 一意の番号
  id: Int,
  name: String,
)

# ふつうのコメント。行末まで
fn main() {
  user = User(id: 1, name: "alice") # 行の途中からでも書ける
  dbg(user.name)
  ()
}
```

- `#` から行末までがコメントです。
- コメントは改行の手前で終わります。`\r\n` の `\r` はコメントに含めません。
- `##` は文書コメントで、直後の宣言、ローカルの fn、バリアント、フィールド、エフェクトの操作、handler の項目に付きます。
- 宣言と `derive` の間に書いた `##` は、宣言に付きません。
- ブロックコメントはありません。

## 名前の字句クラス

名前は形によって3つのクラスに分かれます。

| クラス | 形 | 使うもの | 例 |
|---|---|---|---|
| 小文字名 | 小文字で始まる snake_case | 変数、関数、フィールド、引数名、エフェクトの操作 | `user_id` `find` |
| 型名 | 大文字で始まり、小文字を1つ以上含む PascalCase | 型、構成子、エラー、エフェクト、ハンドラ、layer、Trait、モジュール、型引数 | `User` `Http` `Db` `Item` |
| 大文字名 | 大文字、数字、アンダースコアだけ | const、型引数 | `MAX_SIZE` `A` |

```emela check
const MAX_SIZE = 100

type Item(name: String, size: Int)

fn fits(item: Item) -> Bool {
  item.size <= MAX_SIZE
}

fn main() {
  dbg(fits(Item(name: "box", size: 30)))
  ()
}
```

- クラスに合わない名前はコンパイルエラーです（E1003）。名前全体で1つの誤りとして数え、診断は1つだけ出します（`Http_client`）。`HTTP` や `DB` は型名として使えないので、`Http`、`Db` と書きます。

```emela check=error
type HTTP(status: Int)
```

- 型名と大文字名は、既存の定義を指す名前です。式やパターンの中で新しく束縛されることはありません。そのため、パターン中の打ち間違いは必ず「未定義の名前」としてエラーになります（E2101）。
- `_` は値を束縛しないパターンです。パターンの外には書けません（E1110）。
- 型引数は大文字名（`A`、`T`）と型名（`Item`、`Key`）のどちらでも書けます。型引数を宣言できるのは `[...]` の中だけで、参照できるのは型の位置だけです。式の中に書くと E2106 です。宣言していない名前を型に書くと、未定義の名前のエラーになります（`fn id(x: A) -> A` は E2101）。型名で書いた型引数が型か型引数かは、名前解決で決まります。
- 型引数は同じ名前の外側の型、エフェクト、エラー、Trait を隠します。型名の型引数が隠したときは警告します（W2101）。後から型を足したとき（Prelude への追加を含む）に、既存のコードが壊れないようにするためです。
- 名前に使える文字は ASCII だけです。ASCII でない文字（`é`）は認識できない文字です（E1005）。
- 小文字名が途中に大文字を含むこと（`userId`）と、型名で大文字が続くこと（`HTTPServer`）は、字句としては許します。snake_case と PascalCase の慣習は linter が検査します。

この規則から、`.` の左側を見れば意味が分かります。

- 左が型名なら、静的な参照（モジュールの関数、Trait のメソッド）です。例: `List.map`
- 左が小文字名か大文字名なら、値へのアクセス（フィールド、`use` で得た能力の操作、メソッド呼び出し）です。例: `user.name`、`log.info`、`DEFAULT_CONFIG.port`、`xs.map(f)`

```emela check
fn main() {
  xs = [1, 2, 3]
  ys = List.map(xs, |x| x * 2) # 左が型名: モジュールの関数
  zs = xs.map(|x| x + 1) # 左が小文字名: メソッド呼び出し
  dbg((ys, zs))
  ()
}
```

## リテラル

| 種類 | 形 | 備考 |
|---|---|---|
| 整数 | `42` `1_000_000` `0xFF` `0b1010` | 文脈が Int64 を要求すれば Int64、それ以外は Int。Float にはならない。`0x` は16進、`0b` は2進 |
| 浮動小数点 | `3.14` `1.0e9` | Float |
| 文字列 | `"hello"` `"""..."""` | `#{式}` で補間する。式の型は Show を満たすこと。`"""` で囲むと複数行を書ける |
| リスト | `[1, 2, 3]` `[x, ..rest]` | `List[Int]`。末尾の `..式` は、その前に要素を付けたリストを作る |
| タプル | `(a, b)` | 要素は2つ以上 |
| Unit | `()` | 要素0個のタプル |

真偽値はリテラルでなく Bool の構成子 `True` と `False` です。

```emela check
fn main() {
  count = 1_000_000
  mask = 0xFF
  bits = 0b1010
  big: Int64 = 3_000_000_000
  ratio = 1.0e9
  rest = [2, 3]
  xs = [1, ..rest]
  pair = (count, "items")
  dbg("#{count} #{mask} #{bits} #{big} #{ratio} #{xs} #{pair}")
  ()
}
```

### 数値の細則

- 浮動小数点の指数は小数点のある形にだけ付けられます。`1e9` は書けず、`1.0e9` と書きます。
- 数値の直後に英字が続くもの（`1e9`、`3px`）は字句のエラーになります（E1004）。
- 16進と2進の接頭辞は小文字だけ（`0x`、`0b`）です。16進の数字は大文字と小文字のどちらでも構いません。
- 大文字の接頭辞（`0XFF`）、持たない接頭辞（`0o17`）、数字のない接頭辞（`0x`）、16進と2進の小数（`0x1.5`）は E1004 です。かたまり全体で1つの誤りとして数えます。
- 8進は持ちません。
- 値が文脈の型（Int か Int64）の範囲を超えればエラーになります（E3004）。2の補数として読み替えないので、`0xFFFF_FFFF` は Int では書けず、Int64 なら書けます。
- 負の数はリテラルではなく、単項マイナスを付けた式です。リテラル自体は正の数として範囲を見るので、Int の最小値 `-2147483648` は式のリテラルとしては書けません。式では `-2147483647 - 1` と書きます。
- パターンでは、数のリテラルの前に `-` を書けます（[パターンマッチ](/guide/pattern-matching/)）。範囲は `-` と数を1つの値として見るので、パターンの中では `-2147483648` を書けます。
- `<-` は1つのトークンです（エフェクトの別名 `x <- E`）。負の数との比較は `<` と `-` の間に空白を入れて `a < -1` と書きます。式の被演算子の後の `<-`（`a<-1`、`a <- 1`）と、`x <- R` の R がエフェクトの名前でないもの（`x <- 1`）は E1113 です。

```emela check=error
fn main() {
  x = 0xFFFF_FFFF # error[E3004]: Int の範囲を超える
}
```

```emela check
fn main() {
  x: Int64 = 0xFFFF_FFFF # Int64 なら書ける
  dbg(x)
  ()
}
```

### 文字列の細則

- 文字列は改行をまたげません（E1001）。複数行は `"""` の文字列で書きます。
- `#{ }` の中は普通のコードとして字句解析します。コメントと改行を書けて、改行は継続になります。
- 文字の型（Char）は持ちません。1文字は長さ1の String で表します（[ターゲット](/reference/targets/)）。
- エスケープを解釈しない生の文字列は持ちません。
- 字句は最長一致で切ります。`""""` は `"""` と `"` で、空の文字列 `""` を2つ並べたものとは読みません。

エスケープは次の7つです。それ以外の `\` はエラーになります（E1007）。診断は `\` とその次の1文字を指します。行末の `\` は E1006 です。

| エスケープ | 意味 |
|---|---|
| `\"` | `"` |
| `\\` | `\` |
| `\n` | 改行（U+000A） |
| `\t` | タブ（U+0009） |
| `\r` | 復帰（U+000D） |
| `\#` | `#`。`#{` を補間でなく文字として書くときに使う |
| `\u{...}` | 1〜6桁の16進で書いた Unicode のコードポイント |

`\u{...}` の誤りはすべて E1008 です。`{` か `}` がない、桁数が1〜6でない、サロゲート（D800〜DFFF）、10FFFF を超える値が当たります。診断は `\` から読んだ最後の文字までを指します。

```emela check=error
fn main() {
  s = "\u{D800}" # error[E1008]: サロゲートは書けない
}
```

### 複数行の文字列

```emela check
fn main() {
  id = 1
  query = """
    SELECT *
    FROM users
    WHERE id = #{id}
    """
  dbg(query)
  ()
}
```

規則上、`query` は `"SELECT *\nFROM users\nWHERE id = 1"` と同じ値です。

- 開く `"""` の直後は改行でなければなりません。
- 閉じる `"""` はそれだけで1行に置きます。
- 閉じる `"""` の行のインデントを、各行の先頭から取り除きます。
- 開く `"""` の直後の改行と、閉じる `"""` の直前の改行は含めません。
- 閉じる `"""` より浅くインデントした行（空行を除く）はエラーになります（E1009）。
- インデントは文字の並びとして比べます。空行を除く各行は閉じる `"""` の行のインデントと同じ並びで始まらなければなりません。タブと空白が違う行も浅いとみなします。
- 閉じる `"""` がその行に単独でないときは、インデントを検査しません。
- 複数行の文字列の中の行末の `\` は E1006 で、残りは文字列の本体として読みます。
- 補間とエスケープは、普通の文字列と同じく使えます。

## 行の継続規則

改行は文を終わらせます。ただし次の5つの場合は、前の行が続きます。

1. 次の行が二項演算子、`.`、`escape`、`match` のいずれかで始まる。`match` は、次の意味のあるトークンが `{` のときだけ続けます。後置の match は必ず `match {` なので、正しいプログラムの読み方は変わりません。そうでない行は前置の match として新しい文に読み、E1401 を出します。コンパイラは前置のまま読んで回復し、型の検査は続けます。
2. 開いた `(` または `[` がまだ閉じていない。
3. 次の行が `else` か `->` で始まる。どれも文を始めることがないので、継続にしても曖昧さは生まれません。`} else {` には formatter がそろえます。
4. 次の行が `fails` か `uses` で始まり、その次のトークンが型名、大文字名、`{` のどれかである。fails 節と uses 節は必ずこの形で、ふつうの識別子としての `fails` と `uses` の後にこれらは来ないので、どの位置でも曖昧さは生まれません。本体のない宣言（エフェクトの操作、`@external` の fn）のシグネチャの後や、束縛の型注釈の中でも働きます。本体の `{` は、シグネチャの最後の行に書きます。
5. 次の行が `|` で始まり、前の行が fails 節のエラーの集合の途中（`fails` とエラー、0個以上の `|` とエラーだけ）で終わっている。`fails` は、規則4か規則5で続けた前の行にあっても構いません。それ以外の行頭の `|` は無名関数を始めます。

```emela check
error NotFound(id: Int)
error Invalid

effect Users {
  fn find(id: Int) -> Option[String]
}

fn lookup(id: Int) -> String
  fails NotFound | Invalid
  uses { Users } {
  if id < 0 { fail Invalid }
  users <- Users
  name = users.find(id)
    |> Option.or_fail(NotFound(id:)) # 規則1: 前の行の続き
  parts = [
    "user ",
    name,
    " was found for the id ",
    Int.to_string(id),
    " in the users effect",
    "!",
  ] # 規則2: [ の中
  String.join(parts, "")
}
```

次のトークンで始まる行は、常に新しい文になります。

- `(` と `[`: 関数呼び出しや型引数の開き括弧は、名前と同じ行に書きます。
- `-`: 単項マイナスとして読みます。
- `|`（規則5の場合を除く）: 無名関数を始めます。
- `||`: 引数のない無名関数を始めます。前の行に続く論理和とは読みません（規則1の例外）。

括弧の外では、行末の二項演算子は次の行に続きません。続けるときは `-` と `||` 以外の演算子を次の行の頭に置きます。引き算と論理和の右辺を次の行に書くときは、式を `( )` で囲みます。括弧の中の改行は規則2で続きます。

```emela check
fn main() {
  price = 1_200
  shipping = 500
  a = price
    + shipping
    + price * 2
    + shipping * 2
    + price * 3
    + shipping * 3
    + 1 # 行頭の + は前の行の続き
  c = 10
  -1 # c とは別の文（単項マイナスの式）
  dbg((a, c))
  ()
}
```

補足:

- 継続の判定は改行の次の「意味のあるトークン」を見ます。間の空白、コメントだけの行、空行は飛ばします。
- 規則2の「開いた括弧」は、括弧の入れ子の最も内側で判定します。`(` の中でも、その内側に開いた `{` があれば、改行は文を区切ります（`f(|x| {⏎a⏎b⏎})`）。
- 文字列の補間 `#{ }` の中の改行は、`(` の中と同じく継続になります。
- `type` と `enum` の宣言の直後の行が `derive` で始まるときも、宣言の続きになります。これは字句の継続規則ではなく、宣言の位置でだけ扱う規則です（[文法](/reference/grammar/)）。

```emela check=error
fn main() {
  x = 1
  match x { # error[E1401]: match は後置で書く
    _ -> 0
  }
}
```

## 予約語

予約語は25個で、どの位置でも識別子に使えません。

| 分類 | 語 |
|---|---|
| 宣言 | `fn` `type` `enum` `error` `const` `trait` `impl` `effect` `handler` `layer` `import` |
| 修飾 | `pub` `opaque` `suspend` |
| 式 | `if` `else` `match` `fail` `escape` `use` `with` `assert` |
| 特別な名前 | `self` `Self` |
| 予約のみ | `as` |

`as` は import の別名のための予約語です。まだ構文を持ちません。

## 文脈依存の語

次の語は示した位置でだけキーワードとして働きます。それ以外の位置では普通の識別子です。

| 語 | 位置 |
|---|---|
| `fails` | 関数のシグネチャと関数型 |
| `uses` | 関数のシグネチャと関数型 |
| `derive` | type、enum、error の宣言の末尾、trait の本体 |
| `init` `release` | handler の本体 |
| `of` `default` | ラベルの宣言（[ラベル](/guide/labels/)） |
| `by` | with の項目（[ラベル](/guide/labels/)） |

```emela check
fn main() {
  fails = 1
  init = 2
  by = 3
  default = 4
  dbg(fails + init + by + default)
  ()
}
```

## 将来のための予約

次の語は構文を持ちませんが、識別子にも使えません。

`var` `return` `while` `loop` `let` `mut` `in` `where` `do` `try` `catch` `throw` `async` `yield` `defer` `macro` `mod`

```emela check=error
fn main() {
  var = 1
}
```

## キーワードでないもの

- `True`、`False`、`Some`、`None` は Prelude の enum の構成子です。
- `panic`、`todo`、`dbg` は Prelude の関数です。
- `resume` はハンドラの引数に付ける慣習的な名前です。
- `Immediate`、`Async`、`Eq`、`Capability`、`External` などは組み込みの Trait やエフェクトの名前です。

## 注釈

注釈は `@名前(引数)` の形で、宣言の直前に置きます。使えるのはコンパイラ組み込みの注釈だけで、新しい注釈は定義できません。

| 注釈 | 対象 | 意味 |
|---|---|---|
| `@external(...)` | 本体のない fn | ホスト側の実装を指す。フィールドのない type にも付けられる（[外部関数](/guide/external/)） |
| `@export(...)` | 本体のあるトップレベルの fn | ターゲットごとに、名前を付けて fn をホストに公開する。最初の引数が関数型の `@export` fn はエントリアダプタで、それ自体は公開しない（[外部関数](/guide/external/)） |
| `@entry(...)` | エントリモジュールのトップレベルの fn | エントリアダプタを通して fn を公開する。引数は同じモジュールの fn の小文字名（`serve`）か、修飾した名前（`Http.serve`） |
| `@test` | fn | テスト関数である。引数のある fn、本体のない fn、トップレベルでない fn に付けたり、引数を渡したりすると E2203。テスト関数はテスト関数の中からしか参照できない（値としての参照も同じ。E2204）（[テスト](/guide/testing/)） |
| `@deprecated(...)` | 任意の宣言 | 使用箇所で警告する |
| `@intrinsic` | 本体のない fn、effect、フィールドのない type（同梱の core のソースのトップレベルだけ） | fn では、コンパイラが実装を持つ組み込み関数である。実装は名前でコンパイラの組み込み関数の表から引き、`@external` の制約を満たすものとして扱う。effect では組み込みのエフェクト、フィールドのない type では実行時が値を表す組み込みの型（Bytes）になる。core のソースの外では使えない（E2201）。本体のある fn、ほかの宣言、trait、impl、handler の中の fn に付けると E2202 |
| `@internal` | トップレベルの fn（同梱の core のソースだけ） | core のモジュールの外から参照できない（E2205）。core の外や、トップレベルの fn 以外には付けられない（E2206） |
| `@key("名前")` | type のフィールドと、バリアントの名前付きの中身 | 導出した Encode、Decode、Shaped で、フィールド名の代わりに使うキー |
| `@tag("名前")` | enum のバリアント | 導出した Encode、Decode、Shaped で、バリアント名の代わりに使うタグ |

`@key` と `@tag` の引数は文字列リテラル1つです。`@key` をフィールド以外に、`@tag` をバリアント以外に付ける、同じフィールドやバリアントに2回付ける、ほかの引数を渡す、のどれも E3310 です。1つの型か1つのバリアントでキーが重なる、または1つの enum でタグが重なると E3309 です。導出したコード以外には影響せず、フィールドはこれまでどおり名前で読み書きします。

```emela check
import Std.Dynamic.{Encode}

type User(@key("user_id") id: Int, name: String) derive Encode

enum Shape {
  @tag("circle")
  Circle(radius: Float)
  Square(side: Float)
} derive Encode

fn add(a: Int, b: Int) -> Int { a + b }

@test
fn adds() {
  assert add(1, 2) == 3
}
```
