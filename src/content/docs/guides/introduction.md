Emela は、**Native と WebAssembly へのコンパイル**を想定した、実験的な関数型言語です。
「小さくて、実行時の挙動が明示的で、境界での副作用を型で追跡できる」ことを重視しています。

このページでは、言語を学ぶ前に知っておくと理解が早くなる **設計の柱** を紹介します。
個々の機能の正確な規則は[リファレンス](/reference/values/)にあります。

## 3行でいうと

- 関数が使う **capability（能力＝副作用）** を型の `uses` 節に書く。その集合がそのまま WebAssembly サンドボックスの **権限表** になる。
- **null が無い**。値の不在は `Option<T>`。所有権・借用・move も無い。
- **式指向で不変**。`if` も `match` も block も式。反復は再帰で書く。

## capability を型で追跡する（`uses`）

Emela のいちばんの特徴は、関数が要求する副作用を型に書くことです。
標準出力に書く関数は `uses { Io }` を持ちます。

```emela
import std.io

fn greet(name: String) -> Unit uses { Io } {
    Io.print("hello, " ++ name ++ "\n")
}
```

`uses` に並ぶ `Io` のような名前が **effect（capability）** です。これは二重の保証を生みます。

- **静的**: 宣言していない副作用を使うとコンパイルエラーになります。`uses {}`（純粋）な関数の中で `Io.print` は呼べません。
- **動的**: プログラムが要求する権限は、そのまま WebAssembly モジュールがホストへ求める import 集合になります。import されていないホスト関数は、サンドボックスが実行時にも呼ばせません。

effect は静的な契約です。**型検査が終わると消去され、実行時表現もランタイムコストも持ちません**。
詳しくは[エフェクト（uses）](/reference/effects/)を参照してください。

## null が無い

Emela に null はありません。「値が無いかもしれない」は `Option<T>` という普通の enum で表します。

```emela
match array_get(xs, i) {
    Some(v) -> v
    None -> 0
}
```

失敗の表し方は3つに分かれます。

| 種類 | 表現 |
|---|---|
| 値の不在（「無い」を返す） | `Option<T>` |
| 回復可能な失敗（呼び出し元が対処しうる） | `throws E`（[エラー](/reference/errors/)） |
| 回復不能な異常 | `panic` |

所有権・借用・move semantics も導入しません。メモリはランタイムが管理する非循環ヒープです。

## 式指向・不変

- 束縛（`let`）はすべて **不変**。再代入はできません。
- ループ構文はありません。**反復は再帰**で書きます（自己末尾呼び出しはスタックを消費しないことが保証されます）。
- `if` / `match` / block はすべて **式**（値を返す）で、`return` はありません。

```emela
fn max(a: Int, b: Int) -> Int {
    if a < b { b } else { a }   -- if は式。else は必須
}
```

## 移植可能な意味論

ターゲットによってプログラムの意味が変わることを許しません。`Int` は i32、`Float` は f64 に固定され、
演算の観測可能な意味（整数の wrap・切り捨て除算・0除算 panic など）は全 backend で一致します。
コンパイラ自身は副作用も純粋演算の中身も持たず、実体は境界の外側（ホストと backend）が供給します（→ [ランタイム境界](/reference/runtime-boundary/)）。

## Emela が今 “持たない” もの

実験段階なので、意図的に持たない・まだ無いものがあります。

- 可変変数・ループ構文（不変・再帰で書く）
- null・例外の暗黙伝播（`Option` / `throws` で明示）
- 所有権・借用・GC への依存（ランタイム管理の非循環ヒープ）
- 大きな標準ライブラリ（コアは小さく保つ）
